# OpenBridge v2.1 — Playground, Admin Panel, Professional Stats, Session Health & Catch-up

Professional development plan for the next feature batch. Every feature below is additive:
existing tables/endpoints keep working; new behavior is layered on with a single new migration.

---

## 1. Goals

1. **Character Playground** — users test how any of their characters replies, right in the dashboard, without touching WhatsApp.
2. **Admin Panel** — a proper `admin` role: set the platform LLM gateway (any OpenAI-compatible base URL + bearer token, with current config shown & testable), see every user + their characters, and watch how the whole bridge performs.
3. **Professional Stats** — filterable, paginated, aggregated stats for users AND admin. No view ever loads all rows at once (avoids CPU spikes).
4. **Session Health Notifications** — the moment an OpenWA session disconnects, the user is warned in a Notification center. On reconnect, a second notification fires.
5. **Reconnect Catch-up** — after a session reconnects, wait a few seconds for pending deliveries, re-read recent history, detect messages missed while offline, persist them, and reply to the latest missed message in each affected chat.

## 2. Data model changes — `db/migrations/002_saas_features.sql`

| Change | Why |
|---|---|
| `users.role text NOT NULL DEFAULT 'user'` | distinguish admins; bootstrap admin becomes `admin` |
| `admin_settings` (key text PK, value jsonb, updated_at) | runtime LLM gateway config (`llm_base_url`, `llm_bearer`, `llm_default_model`) seeded from env |
| `notifications` (id, user_id, session_id, type, level, title, body, read, created_at) | Notification center per user |
| `wa_sessions.disconnected_at timestamptz` | track offline window for catch-up |
| `messages.remote_id text` | idempotency for catch-up dedup (OpenWA message id) |
| index `messages(user_id, created_at)` | fast time-range stats |

### Notification types
- `session_disconnected` (level warning) — session went offline.
- `session_reconnected` (level success) — session came back online.
- `catchup_missed` (level info) — N missed message(s) detected + reply sent.
- `system` (level info) — admin/global messages.

### LLM gateway resolution (new service `src/services/gateway.js`)
- Reads `admin_settings` (cached 30s in memory), falls back to env `OMNIROUTE_BASE_URL`/`OMNIROUTE_BEARER`.
- `PUT /api/admin/llm` writes to DB + busts cache → takes effect immediately, no redeploy.

## 3. New / changed backend endpoints

### Playground (user)
- `POST /api/playground` `{ characterId, message, history?: [{role,content}] }`
  - Builds the character system prompt, appends optional history + message, calls the LLM gateway.
  - Returns `{ reply, model, latencyMs }`. **Never persisted** → stats stay clean.

### Notifications (user)
- `GET /api/notifications?limit&page&unreadOnly`
- `GET /api/notifications/unread-count`
- `POST /api/notifications/read` `{ ids?: [...] }` (or all)

### Admin (`role === 'admin'`)
- `GET /api/admin/stats?range&from&to&userId&sessionId&characterId&page&perPage`
  - Totals + **per-session (per-number)** breakdown (inbound/outbound/reply-rate/last-seen),
    **per-character** breakdown, **per-user** breakdown. SQL aggregation + LIMIT/OFFSET + total count.
- `GET /api/admin/users?search&page&perPage` — user list (email, name, plan, role, msgs, chars, sessions, last active).
- `GET /api/admin/users/:id` — user detail: profile, characters, sessions, per-session message stats, recent messages (paginated).
- `GET /api/admin/llm` — current gateway config (bearer masked).
- `PUT /api/admin/llm` `{ llm_base_url, llm_bearer, llm_default_model }`.
- `POST /api/admin/llm/test` — one-shot call against provided config, returns ok/err + latency.

### Enhanced user dashboard (existing routes upgraded)
- `GET /api/dashboard/stats?range&from&to&sessionId&characterId`
  - Existing totals + time-range-aware + per-session & per-character breakdown.
- `GET /api/dashboard/messages?page&perPage&chatId&direction&characterId&sessionId&from&to`
  - Paginated (was: limit 100 grab-all). Returns `{ items, total, page, perPage, pages }`.

### Sessions (existing route upgraded)
- `GET /api/sessions` now returns `disconnected_at` + a `connected` boolean derived from status.

## 4. Session health & catch-up (services/bridge.js + server.js poller)

### Disconnect / reconnect detection (in the existing 30s poller)
- Track prior status per session.
- `ready|active|connected` → online. Everything else (`qr_ready`, `connecting`, `disconnected`, `error`, …) → offline.
- **Offline transition** → `disconnected_at = now()` + `session_disconnected` notification.
- **Online transition** → `disconnected_at = NULL` + `session_reconnected` notification + schedule catch-up.

### Catch-up (`catchUpSession(user, session)`)
1. Wait `RECONNECT_WAIT_MS` (default 8000ms) so pending deliveries land.
2. For every chat the tenant has seen (distinct `chat_id` from `messages`), fetch recent history from OpenWA.
3. Dedup by `remote_id` (fallback: chat_id + body + time window) — skip rows already persisted.
4. If a chat had missed **incoming** messages: persist them, then generate **one** reply to the **latest** missed
   message (with history context), send via OpenWA, persist the outgoing, notify `catchup_missed`.

This guarantees: no double replies to the same message, and the AI never misses an important offline message.

## 5. Frontend (public/)

| View | Contents |
|---|---|
| **Notification bell** (sidebar, always visible) | unread badge, dropdown list, mark-all-read |
| **Playground** (per character, in character editor) | message input, optional context, reply bubble, model + latency shown |
| **Stats** (user, new nav item) | metric cards + time-range filter (7d/30d/90d/custom), per-session & per-character tables, paginated message table with filters |
| **Admin** (nav item, only for `role=admin`) | Overview stats w/ filters + pagination · Users list (search + pagination, click → user detail: chars + sessions + per-number stats + messages) · LLM gateway (view masked token, edit, save, test) |

All tables use **server-side pagination** — the UI never fetches more than a page at a time.

## 6. Admin credentials

- Email: `ADMIN_EMAIL` (default `admin@openbridge.local`) · Password: `ADMIN_PASSWORD` (default `admin12345`) — set both in `.env`.
- These are the login for the admin panel (same `/api/auth/login` flow; the `admin` role unlocks the admin nav + routes).
- The login screen shows them when `ADMIN_SHOW_CREDS=true` (default) so operators can find them; disable in production.

---

## 7. Performance guarantees (professional requirement)

- Every list endpoint is `LIMIT/OFFSET` with a `COUNT(*)` total → bounded rows regardless of dataset size.
- All aggregates are computed in SQL (`GROUP BY`) — no loading all rows into Node.
- Notification unread-count is a lightweight `COUNT`.
- LLM gateway config is cached (30s TTL) → not read from DB on every LLM call.
